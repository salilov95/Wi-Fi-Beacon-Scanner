# Контракт

[English](README.md) · **Русский**

Что программа должна выдавать на фиксированном наборе сканов. Это договор между версией на Python (1.x)
и версией на Rust + Tauri (2.x, в разработке): на одних и тех же входных данных обе должны давать один результат.
Заодно это защита самой 1.x: любое изменение разбора или правил видно здесь как расхождение.

| Путь | Что |
|---|---|
| `fixtures/*.json` | Вход: снапшоты сканов (формат «Экспорт → JSON») |
| `golden/<снапшот>.<язык>.json` | Эталонный выход для каждого снапшота на русском и английском |
| `schema/golden.schema.json` | Формат эталона (JSON Schema 2020-12) |
| `i18n/en.json` | Английский каталог переводов, общий для обеих версий (выгружает `tools/export_i18n.py`) |
| `journal/` | Журнал подключения и сессии: сценарии событий (`scenarios/`) и результат 1.x (`golden/`), `tools/journal_contract.py` |

В эталоне для каждого снапшота:

- `bss` - каждая строка таблицы сетей так, как её видят таблица и вкладка «Beacon», с деревом IE;
- `findings` - вкладка «Проблемы»;
- `advice` - свободность каналов 2.4 и 5 ГГц (`count` - BSS, `radios` - радиомодули);
- `util` - загрузка каналов по QBSS Load.

## Снапшоты

| Снапшот | Откуда |
|---|---|
| `real-home-01` | реальный скан (MediaTek MT7921, Windows 11), обезличен |
| `demo-office` | один скан демо-режима (`DemoBackend`: RSSI уже покачан, слабый BSS пропал) |
| `demo-base` | сам демо-офис, `build_demo_snapshot()`; его качает `--demo` в 2.x. Пишет `tools/make_contract_fixtures.py` |
| `synthetic-edge` | собранные вручную крайние случаи: устаревшая ширина VHT, AKM 23/24/25, FILS, 6 ГГц канал 2, одно радио с несколькими SSID |
| `synthetic-coverage` | собран `tools/make_contract_fixtures.py`, чтобы пройти по веткам разбора IE и правил (ничьи, Tx MCS Set, TPC, флаги 6 ГГц, 802.11u, vendor IE...) |

Реальные сканы перед коммитом обезличиваются: репозиторий публичный, а в скане названия и BSSID соседних
сетей и, в WPS, модели и серийные номера роутеров.

    python tools/anonymize_snapshot.py скан.json contract/fixtures/real-<место>-NN.json

SSID становятся `net-01…`, у BSSID остаются OUI вендора и младшие 4 бита (вендор и группировка в радио не
меняются), текст в WPS и vendor IE затирается. Если в результате остался хоть один исходный SSID или BSSID,
файл не записывается. Исходный скан и файл `--map` в репозиторий не класть.

## Команды

    python tools/golden.py check     # пересчитать и сравнить (это же делает tests/test_contract.py)
    python tools/golden.py diff      # показать, что отличается
    python tools/golden.py update    # перезаписать эталоны - только если изменение задумано

Числа сравниваются с допуском 1e-6: программа их уже округляет, допуск только против разницы в последнем бите
между платформами.

## Правила

1. Изменение, которое меняет `golden/`, должно быть задуманным, описанным в CHANGELOG и закоммиченным вместе с
   пересчитанными файлами (`update`). PR с необъяснённым расхождением эталонов - это регрессия.
2. Новый снапшот кладётся в `fixtures/`, затем `update`; эталоны на обоих языках создаются сами.
3. Новое поле в выходе сначала добавляется в схему. Номер `contract` растёт, только если у существующего поля
   меняется смысл или тип.
4. Версия на Rust читает те же `fixtures/` и сравнивает свой выход с теми же `golden/`.
