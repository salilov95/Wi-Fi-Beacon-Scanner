## Что проверяется (вкладка «Проблемы»)

Всего 29 проверок. У каждой проблемы в программе есть пояснение и подсказка «что проверить».

| Код | Что находит | Важность |
|---|---|---|

| `RF_UTIL` | Высокая загрузка канала | внимание / критично |

### Гигиена сети

| Код | Что находит | Важность |
|---|---|---|
| `HYG_BASIC_RATES` | 2.4 ГГц: 802.11b-скорости в basic rate set | информация |
| `HYG_HT_PROT` | HT protection включён | информация |
| `HYG_LEGACY_PHY` | BSS без HT (только 802.11a/b/g) | внимание |
| `HYG_24_ONLY` | SSID слышен только в 2.4 ГГц | информация |
| `HYG_HIDDEN` | Скрытые SSID | информация |

`RF_COCHANNEL`, `RF_UTIL` и оценка свободности каналов считают радиомодули, а не BSSID: несколько SSID
одной AP - один передатчик. Радио - это BSS на том же канале, той же ширине и центре полосы, у которых BSSID
отличается только младшими 4 битами последнего октета (Multiple BSSID и раздача адресов у большинства
вендоров). Если вендор раздаёт BSSID иначе, такие BSS считаются разными радио.

Пороги лежат в `Thresholds` (`wifi_beacon_scanner/rules.py`); из CLI пока меняется только `--weak-rssi`.

Проблемы ищутся по всему эфиру. Ошибки конфигурации и слабого сигнала - только для «Моих SSID»,
чужие сети учитываются как помеха на канале. В отчёт попадают проблемы, которые касаются выбранных сетей.

## Дополнения 802.11 (колонка «802.11» и фильтр)

Что точка объявляет в beacon / probe response. Это заявленные возможности, а не проверка их работы.

| Код | Откуда берётся |
|---|---|
| d | Country IE (7) |
| e | WMM (vendor IE 00-50-F2 тип 2), EDCA Parameter Set (12) или бит QoS в Capability Information |
| h | бит Spectrum Management в Capability Information, Power Constraint (32), TPC Report (35), Channel Switch Announcement (37) |
| i | RSN IE (48) |
| k | RM Enabled Capabilities (70), отдельно - есть ли neighbor report |
| r | Mobility Domain (54), MDID и FT over DS |
| u | Interworking (107) или бит 31 Extended Capabilities; тип сети, флаг «интернет», ANQP (108), Roaming Consortium (111) |
| v | бит 19 Extended Capabilities (BSS Transition); дополнительно Proxy ARP, WNM Sleep, TFS, DMS, TIM Broadcast, WNM Notification |
| w | PMF в RSN Capabilities: поддерживается (MFPC) или обязательна (MFPR) |
| mc | FTM responder / initiator, биты 70/71 Extended Capabilities |
| ai | FILS, бит 72 Extended Capabilities |
| s | Mesh ID (114) |
| TWT | HE MAC Capabilities (TWT Responder) или бит 78 Extended Capabilities |
| MBSSID | Multiple BSSID (71) или бит 22 Extended Capabilities |
| HS2.0 | Hotspot 2.0 Indication (vendor IE 50-6F-9A тип 0x10) |

Фильтр «802.11» в строке фильтров: «есть все отмеченные» или «нет ни одного из отмеченных», рядом с
каждым пунктом - сколько BSS в эфире его объявляет. Все включённые биты Extended Capabilities видны
на вкладке «Beacon».

## Шкала сигнала

Везде одна шкала от красного к зелёному: −85 дБм и ниже красный, −75 оранжевый, −67 жёлтый, −60 салатовый,
−50 и выше зелёный. Ориентиры: от −67 и сильнее хватает для голоса и видео, −67…−72 для данных, слабее −75
клиенты начинают терять скорость и роумиться. Загрузка канала окрашена наоборот: до 30% свободен,
30–50% умеренная, 50–70% высокая, от 70% перегружен.

## Загрузка канала

Берётся из QBSS Load (IE 11) в beacon: доля времени, когда сама AP считает канал занятым, и число станций.
Вещают не все AP: нет IE - нет цифры, а не «0%». На канал берётся максимум среди AP, которые сообщают загрузку.

## MCS и максимальная скорость

Beacon не содержит «текущий MCS». В нём есть то, что AP умеет:

- HT Capabilities: Rx MCS bitmask (например, MCS 0-15 = 2 потока), Short GI 20/40;
- VHT Capabilities: Rx/Tx VHT-MCS map по потокам (MCS 0-7/0-8/0-9), Short GI 80/160, ширины сверх 80 МГц, beamforming;
- HE Capabilities: Rx/Tx HE-MCS map до 80 МГц и для 160 МГц (MCS 0-7/0-9/0-11);
- HT/VHT/HE Operation: Basic MCS Set - минимум, который AP требует от всех клиентов; в HE Operation ещё
  BSS Color и для 6 ГГц ширина и центр канала (раньше 6 ГГц всегда считался 20 МГц).

Из этого считается «Макс. PHY»: скорость канального уровня по формуле стандарта для старшего MCS, числа
потоков AP, рабочей ширины канала и самого короткого GI, который AP поддерживает. Это потолок при идеальном
сигнале и клиенте с тем же числом потоков, а не пропускная способность (TCP получится примерно вдвое меньше).

MCS, с которым реально идут кадры, виден только в monitor mode (radiotap), Native Wifi API его не отдаёт.
Для своего подключения Windows сообщает скорость приёма и передачи; программа подбирает MCS, число потоков,
ширину и GI, которые дают ровно эту скорость (вкладка «Подключение», «MCS по скорости»). Совпадений бывает
несколько (MCS 4 на 2 потока и MCS 8 на 1 поток почти равны), первым показан вариант с шириной BSS и двумя
потоками, остальные в подсказке. EHT (Wi-Fi 7) MCS пока не разбирается: для таких AP показан HE-потолок.
